# 외부 AI로 나가는 내용 보호 설계

- 작성일: 2026-10-18
- 배경: 실제 Claude 연결이 준비됐다(`PROVIDER=claude`). 켜는 순간 사용자의 요청 글·답·보완 정보가 외부 API로 나가고, 프롬프트는 서버 trace(DB)에도 남는다. 지키려는 것은 **개인정보**(주민번호·연락처·계좌 등)와 **사업 비밀**(공개 전 아이디어·원가·거래처 등) 둘 다다.
- 범위: 비용 0 프로토타입에서 실제로 동작하는 보호(Mock에서도 확인·시연 가능). 실제 호출과 업체 계약은 인수 기업 몫이다.

## 1. 결정 사항 (사용자 확정)

| # | 주제 | 결정 |
|---|---|---|
| 1 | 보호 대상 | 개인정보와 사업 비밀 둘 다 |
| 2 | 구현 수준 | 동작하는 보호 기능(자동 가리기·비공개 항목·고지 동의)과 남은 위험 문서화 |
| 3 | 비공개를 정하는 쪽 | 과제 정책이 기본값(`private_fields`), 사용자가 답마다 바꾼다 |
| 4 | 개인정보 가리기 | 정해진 패턴을 표시 글로 바꾸고 되돌리지 않는다 |
| 5 | 비공개 설정 전달 | 따로 요청을 두지 않고 답변·답 고치기·보완 정보 저장 요청에 `private`를 함께 싣는다 |
| 6 | 동의 | 요청 화면에서 고지에 체크해야 보낼 수 있고, 세션에 고지 버전과 동의 시각을 남긴다 |

## 2. 원칙

- **외부로 나가는 길목은 하나다.** LLM은 `BaseHarness._call`, 이미지는 `BaseHarness.illustrate`가 프롬프트를 만들어 제공자를 부른다. 거르기는 이 두 곳이 같이 쓰는 함수 하나(`outbound_prompt`)로 한다.
- **세션 상태는 그대로다.** 서버 안의 사실·보완 정보·요청 글에는 원래 값이 남는다(화면·결과 문서·내려받기에는 사용자 자신의 값이 보인다). 걸러지는 것은 **프롬프트와 trace**뿐이다.
- 판단은 순수 함수, 상태 변경은 하네스 메서드 한 곳(기존 규칙).

## 3. 백엔드

### 3.1 비공개 항목
- 정책 `TaskPolicy.private_fields: list[str]` — 필드 또는 보완 항목 이름. 읽을 때 정책에 있는 이름인지 확인한다(모르는 이름은 거부).
  - 시작값: 상품기획 `production_cost`·`sale_price`, 사업계획 `revenue_model`·`production_cost`·`sale_price`·`budget`, 마케팅 `price`, 브랜딩 없음.
- 세션 `SessionState.private_overrides: dict[str, bool]` — 사용자가 바꾼 것만 둔다.
- 순수 함수 `private_names(defaults, overrides) -> frozenset[str]` — 정책 기본값에 사용자 설정을 덮은 결과.
- 요청 본문 `AnswerRequest.private`, `ReviseAnswerRequest.private`: `bool | None`(없으면 그대로) — 그 질문의 필드에 적용. `SupplementsRequest.private: dict[str, bool]`(없으면 빈 사전) — 항목별 적용. 모르는 이름은 422. 값을 바꾸는 하네스 메서드(`apply_answer`·`revise_answer`·`set_supplements`)가 같은 원자적 블록 안에서 `private_overrides`도 고친다(`_set_private`, 정책 기본값과 같아지면 덮어쓴 값을 지운다).
- 비공개 설정만 바뀌어도 결과가 있으면 다음 생성 프롬프트가 달라지므로 `result_stale`을 다시 정한다: 버전에 `private` 이름 집합을 스냅샷해 두고, "답·보완 정보·비공개 집합이 마지막 버전과 다른지"로 판단한다(`answers_changed`·`supplements_changed`와 같은 방식의 `privacy_changed`).

### 3.2 프롬프트 거르기
- 순수 함수 `masked_state(state, private) -> SessionState`(복사본): 비공개 이름의 사실·가정·보완 정보 값을 `[비공개 입력 · AI에 보내지 않음]`으로 바꾼다. 미정·출처는 그대로라 AI는 "있다"는 것만 안다. 이어가기 맥락(`context.items`)의 같은 이름 값도 바꾼다.
- 순수 함수 `redact(text) -> tuple[str, dict[str, int]]`: 아래 패턴을 표시 글로 바꾸고 종류별 개수를 돌려준다(겹치면 앞 줄이 먼저).

| 종류 | 표시 | 패턴(요지) |
|---|---|---|
| 주민등록번호·외국인등록번호 | `[주민번호]` | `\d{6}-?[1-8]\d{6}` |
| 카드번호 | `[카드번호]` | 4-4-4-4 숫자(공백·하이픈 허용) |
| 계좌번호 | `[계좌번호]` | 숫자 2~6자리 그룹 3~4개를 하이픈으로 이은 것(전화번호·주민번호가 아닌 것) |
| 휴대전화·유선전화 | `[전화번호]` | `01[016789]`·`0\d{1,2}`로 시작, 하이픈·공백·점 허용 |
| 이메일 | `[이메일]` | 일반 이메일 형식 |

  가격·수량(예: `18,000원`, `2026년`, `500개`)은 가리지 않는다(테스트로 고정).
- 순수 함수 `outbound_prompt(prompt) -> tuple[Prompt, dict[str, int]]`: system·user 둘 다 `redact`.
- `_call`과 `illustrate`는 `masked_state`로 렌더한 뒤 `outbound_prompt`를 거친 프롬프트만 제공자에 보내고 trace에 남긴다. trace 항목에 `redactions`(종류별 개수)를 더한다.

### 3.3 동의 기록
- `CreateSessionRequest.notice_acknowledged: bool`(필수, false면 422 "외부 전송 안내를 확인해 주세요.").
- 세션 `notice_version: str`(지금 `"2026-10-18"`, 상수 `NOTICE_VERSION`)과 `notice_acknowledged_at: datetime`. 고지문을 바꾸면 버전을 올린다.

### 3.4 응답
- 기준 표 항목에 비공개 여부를 싣는다: `SummaryItem.private: bool`, `SupplementItem.private: bool`.
- 질문에는 따로 싣지 않고 `SessionView.private_names: list[str]`(정렬)을 준다. 질문 카드·답 고치기는 `field in private_names`로 기본 체크를 정한다.
- 버전은 그때의 비공개 이름을 `ResultVersion.private: list[str]`로 스냅샷한다(3.1의 `privacy_changed`가 쓴다).
- 결과·버전 보기의 기준 표(`ResultView.summary`, `supplements`)는 그 버전의 비공개 집합으로 `private`를 채운다.

## 4. 프론트

- **요청 화면**: 입력창 아래 고지 문구와 체크 칸 "확인했어요"(체크해야 요청 전송 가능). 체크 여부는 쓰다 만 요청 글처럼 과제별로 앱 상태에 두고, 세션을 만들 때 `notice_acknowledged`로 보낸다(모드 화면은 체크된 경우에만 모드 버튼이 열린다).

  > 입력 내용은 결과를 만들기 위해 외부 AI 서비스로 전송될 수 있어요. 개인정보(주민번호·연락처·계좌 등)는 자동으로 가려서 보내고, 'AI에 보내지 않음'으로 표시한 항목은 보내지 않아요. 공개 전 아이디어·영업비밀은 표시해 주세요.

- **질문 카드·답 고치기**: 입력 아래 "🔒 이 답은 AI에 보내지 않기" 체크 칸(기본값은 `private_names`), 답을 보낼 때 `private`를 싣는다.
- **미확인 정보 입력**: 항목마다 같은 체크 칸, 저장할 때 `private` 사전.
- **답변 확인·결과 문서·내려받기 기준 표**: 비공개 항목 옆에 "AI에 보내지 않음" 표시.
- 판단은 `lib/privacy.ts`(기본 체크, 보낼 값 계산), 체크 상태는 각 입력 부품이 가진다.
- 미리보기 프레임: `request`(고지), `question-private`(비공개 체크된 질문), `confirm-private`(표시가 있는 확인 화면).

## 5. 오류

- 고지 미확인 세션 만들기: 422.
- 모르는 비공개 이름: 422.
- 기존 오류 계약 그대로(문구는 `messages.py`).

## 6. 테스트

- `redact`: 종류별 가리기, 개수, 가격·연도·수량은 그대로, 겹치는 패턴 우선순위.
- `private_names`: 기본값·덮어쓰기·되돌리기.
- 비공개 항목 값과 개인정보가 **모든 단계 프롬프트와 trace 어디에도 없다**(과제 4개·단계별, Mock).
- 비공개 설정만 바꿔도 결과가 최신 아님이 되고, 되돌리면 다시 최신.
- API: 고지 미확인 422, `private` 반영, 응답의 `private_names`·`private` 표시.
- 프론트: 고지 체크 전 전송 불가, 기본 체크, 요청 본문의 `private`, 미리보기 프레임.

## 7. 이번에 막지 못하는 것 (문서화 → 인수 기업)

- 사용자가 자유 문장 속에 쓴 사업 비밀(패턴이 없어 자동으로 못 가린다) — 고지와 비공개 표시로 안내한다.
- 프롬프트 주입(사용자 입력이 지시처럼 행동) — 시스템·사용자 블록 분리는 이미 있음. 출력 검증 강화는 그쪽 몫.
- 서버 DB 평문 저장, 로그인 없는 익명 ID, 보관 기간·삭제 기능.
- 외부 AI 업체의 데이터 보관·학습 정책 확인과 계약(예: 상업 API의 학습 미사용·보관 기간), 개인정보 처리방침 작성.
