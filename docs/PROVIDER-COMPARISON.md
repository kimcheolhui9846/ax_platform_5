# 제공자 비교: Claude vs OpenAI (TC3)

같은 평가 시나리오를 Claude와 GPT로 돌려 시간·토큰·비용·결과 품질을 비교했다. 테스트 케이스 TC3-1(수동, 실제 호출)의 근거 문서다.

## 실행 조건

| 항목 | 값 |
|---|---|
| 실행일 | 2026-11-04 (개발자 PC, 한 번) |
| 명령 | `uv run --directory backend python ../scripts/compare_providers.py --providers claude openai --budget-usd 5 --out data/compare/tc3-20261104` |
| Claude | `claude-sonnet-5-5`, 노력 `medium`, BAZE 게이트웨이 |
| OpenAI | `gpt-6.1-terra`, 노력 `medium`, BAZE 게이트웨이(Chat Completions strict JSON Schema) |
| 시나리오 | 과제 5개 × `evals/*.yaml` 2개(기본 흐름, '모두 모름' 빠른 모드) = 10개, 제공자마다 1번씩 모두 20회 |
| 방식 | 한 번 호출(`single`). 병렬 생성은 모든 과제에서 꺼져 있다 |
| 이미지 | Mock(SVG 자리표시, 비용 0). 브랜딩·마케팅의 호출 3번 중 1번이 이미지다 |
| 예산 | 상한 $5(제공자마다 $2.5), 실제 추정 사용 약 $0.52 |

모델 선택은 배포(렌더) 설정과 같게 두었다. 두 모델은 단가가 다르다(Sonnet $2/$10, terra $1/$5, 1M 토큰당 입력/출력). 같은 단가 등급끼리 비교하려면 실행할 때 환경 변수 `OPENAI_MODEL=gpt-6.1-sol`로 덮어 다시 돌린다.

## 합계

| 제공자 | 실행 | 완료 | 실패 호출 | 생성 p50(ms) | 생성 p95(ms) | 생성 평균(ms) | 질문 평균(ms) | 입력 토큰 평균 | 캐시 읽기 평균 | 출력 토큰 평균 | 경고 평균 | 계획 어긋남 | 비용 합($) |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| claude | 10 | 10 | 0 | 21129 | 34773 | 22889 | 2345 | 550 | 1962 | 3413 | 0.2 | 0 | 0.4053 |
| openai | 10 | 10 | 0 | 17833 | 46096 | 24558 | 2939 | 1534 | 714 | 1949 | 0.1 | 0 | 0.1135 |

- 토큰은 실행(시나리오) 하나의 합이다. Claude는 system 앞부분을 캐시로 쓰기·읽기 해서 입력 토큰이 적게 잡히고, 캐시 쓰기(평균 1962)·읽기 비용은 비용 합에 들어 있다.
- 시간은 벽시계(게이트웨이 경유)이고 한 번씩만 돌렸으므로 p95는 과제 하나(IR)의 값에 가깝다.
- '생성 평균'과 '캐시 읽기 평균'은 `compare.md`에 없는 칸이라 `rows.csv`에서 계산했다(`compare.md`의 호출 평균 2.4·유출 차단 0은 이 표에서 뺐다).

## 결과 글 비교 (documents/를 읽고)

- **둘 다 하네스 규칙을 지켰다.** 20회 모두 과제 스키마를 통과해 완료됐고(실패·잘림·거절·유출 차단 0), 확인되지 않은 정보는 지어내지 않고 '확인할 것'(주로 Claude)이나 '확인되지 않았습니다·확인한 뒤 정하겠습니다'(주로 GPT) 같은 문장으로 남겼다. IR에서 처음부터 AI에 보내지 않는 금액은 둘 다 '(금액 직접 기입)'으로 비워 두었다.
- **IR 슬라이드 원고:** Claude는 두 시나리오 모두 슬라이드 10장, GPT는 10장·9장('모두 모름' 빠른 모드에서 표지를 빼고 문제부터)을 순서대로 카드에 싣고 슬라이드 종류를 한국어 이름(표지·문제·해결·시장…)으로 썼다(#37 지침 수정이 GPT에도 통했다). Claude는 `[표지] 제목` 형식에 짧은 원고, GPT는 `표지 — 제목` 형식에 더 긴 원고(결과 글 길이 Claude 약 2.0~2.9KB, GPT 약 3.5~3.7KB)였다.
- **IR 경고는 둘 다 오탐이었다.** Claude 2건(`시장 규모`), GPT 1건(`매출 전망`) 모두 근거 없는 수치를 쓴 것이 아니라 "시장 규모 수치는 근거를 확인한 뒤 넣겠습니다", "매출 전망은 검증된 근거를 확보한 후 제시하겠습니다"처럼 **쓰지 않겠다는 문장**에 금지어 규칙(`term_rule`)이 걸렸다. 하네스 튜닝 과제로 남긴다(검증 규칙이 숫자와 함께 쓰인 경우만 보게 하는 등).
- **사업계획:** Claude는 번호 붙은 항목(고객 문제~이번 주 검증 계획)을 짧은 문장으로, GPT는 같은 항목을 존댓말 문단으로 조금 더 길게 썼다(기본 흐름 1.2KB vs 1.5KB). 둘 다 이번 주 계획을 구체 행동(직장인 5명 인터뷰 등)으로 냈다.
- **상품기획:** Claude는 `■ 진단·제안·실행 과제·가정한 항목`(빠른 모드는 `[진단]·[제안]·[실행 과제]`) 묶음으로, GPT는 고객 문제·가치제안·핵심 구성·MVP·가격 방향·확인 및 검증(빠른 모드는 진단·가치제안 가설·핵심 구성 및 MVP·가격 방향·검증 과제) 문단으로 썼다. 사업계획과 달리 둘 다 '이번 주' 단위 계획은 없었다. 길이는 비슷했다(기본 흐름 약 1.0KB로 같고, 빠른 모드 1.0KB vs 0.9KB).
- **마케팅 '모두 모름' 빠른 모드:** GPT 결과 글이 짧았다(약 0.4KB, 콘텐츠 2개 두세 문장). Claude는 같은 시나리오에서 약 1.1KB였다.

## 정리

| 기준 | 더 나은 쪽 | 근거(이번 한 번의 실행) |
|---|---|---|
| 비용 | GPT(terra) | 같은 10개 시나리오에 $0.11 vs $0.41 (단가 차이가 크다) |
| 생성 속도(일반 과제) | 비슷 | 평균으로 사업계획만 Claude가 약 2.9초 빠르고, 상품기획·브랜딩·마케팅은 GPT가 약 1.5~3.9초 빠름 |
| 생성 속도(IR, 긴 출력) | Claude | 평균 32초 vs 45초 |
| 안정성 | 같음 | 20회(제공자마다 10회) 모두 실패 호출 0 |
| 결과 분량 | 과제마다 다름 | IR은 GPT가 길고, 마케팅 빠른 모드는 Claude가 길다 |

한 번씩 돌린 결과라 속도 차이는 게이트웨이 상태에 따라 바뀔 수 있다. 품질 판정(채점 기준표, 사람 2명)은 `docs/EVALUATION.md` 3장의 비교 실험에서 한다. 이 문서는 두 제공자 모두 하네스 계약(스키마·확인할 것·비공개 금액)을 지키며 끝까지 완료되는지와 비용·시간 규모를 보인다.
